# Documentation Style Guide

- Audience: developers and integrators
- Voice: concise, actionable, example-driven
- Headings: use `###` and `##`, avoid top-level `#` in inline docs snippets
- Code blocks: include runnable examples when possible
- Types: document parameter and return types explicitly
- Errors: list error cases with actionable remediation
- Versioning: note `Since` and breaking changes
- Cross-links: link related APIs and components
